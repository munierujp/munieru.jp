# AI向けの作業手順

継続的な作業方針はルートの[AGENTS.md](../AGENTS.md)に置き、この文書では作業の進め方と記録方法を補足します。実装の背景は既存の設計・開発・内容更新ガイドで管理し、AI専用の別仕様は作りません。

## 作業を始めるとき

最初に`git status --short`・現在のブランチ・差分を確認し、依頼前からある変更と今回の変更を区別します。利用者の変更を破棄したり、関係のない修正を一緒にコミットしたりしません。

依存バージョンとコマンドは`package.json`・`.nvmrc`、公開先は`netlify.toml`、現在の実装はソースを確認します。チャットの過去の説明や、以前取得した検証結果だけを現状の根拠にしません。環境構築と各コマンドの前提は[開発・検証ガイド](development.md)に従います。

PRを扱う場合は、現在のブランチで`gh pr view --json number,url,baseRefName,headRefName,headRefOid,body`を実行して対象を特定します。PR番号・ベースブランチ・HEADを固定値として引き継ぎません。Issueの状態・レビューの解決状態・チェック結果も、その都度取得します。

## レビューを確認するとき

PR全体へのコメント・レビュー本文に加え、GitHub GraphQL APIの`reviewThreads`でスレッド内の返信も確認します。最初の100件だけで判断せず、スレッド一覧と各スレッドのコメントの両方で`pageInfo.hasNextPage`を確認し、続きがあれば取得します。

各スレッドでは、`isResolved`・`isOutdated`、対象のパス・行、コメント本文・URL・時刻を確認します。`isOutdated`は古い差分に付いたという意味であり、解決済みとは限りません。追加返信がある場合は、最初の指摘だけでなく最新の質問まで読みます。

人とCodexが同じアカウントで投稿することがあるため、ログイン名だけで発言を分類しません。Codexの識別表記と本文を確認し、判別できない発言を自動で書き換えません。

修正後は該当スレッドへ、変更した内容・コミット・検証結果を返信します。変更しない場合は、削除したときに変わる仕様と維持する理由を具体的に説明します。以前の回答から判断を変えた場合は、関連スレッドにも新しい結論を記載します。

未解決一覧を投稿する直前に状態を再取得し、現在の未解決スレッドだけを列挙します。各行にはレビューコメントへの直接リンク、対応内容、必要に応じて個別回答・修正コミットへのリンクを付けます。回答済みの確認待ちと、未回答・未修正を区別します。

## 検証結果を記録するとき

変更に必要な検証を選び、同じ内容を理由なく繰り返しません。文書だけの変更では、参照先・記載するコマンド・実装との整合・空白を確認し、Secretlintの対象にも含めます。コード・設定・表示の確認条件は開発・検証ガイドに従います。

SEO・多言語の整理では、変更前後の生成HTMLを比較できる状態にします。日英トップではタイトル・メタタグ・言語属性・canonical・hreflangを確認します。静的404はSPAフォールバックなので、専用の案内・言語別OGPは初期HTMLにはありません。JavaScript初期化後の言語・メタ情報・画像・未知URLの維持・通常ページへの復帰と、配信時のHTTP 404を確認し、生成HTMLの検証と区別して記録します。

開発サーバーでの確認だけを、Netlify配信の確認として扱いません。`_redirects`やレスポンスヘッダーは、対応する配信環境で確認します。ツールが使えず確認できなかった場合は、確認済みと記載しません。

一時的な比較ページや検証スクリプトのパス・ポートは、継続して使える手順として文書へ固定しません。検証後は今回起動した不要なサーバーや一時ファイルを片付け、利用者が使っている開発サーバーは停止しません。

## PR本文のコード量を集計するとき

比較元は対象PRのベースブランチとHEADの共通祖先とし、両方のコミットIDを記録します。各コミットの追跡ファイルを`git ls-tree -r --name-only <コミット>`で列挙し、`git show <コミット>:<パス>`の内容を集計します。単なる追加行・削除行の差分だけでなく、変更前後それぞれの総行数を示します。

行数は空行・コメントを含む物理行数とし、末尾改行のない最終行も1行と数えます。ロックファイル・生成物・依存パッケージ・画像・SVG・Markdownは除外し、前後で同じ分類を使います。

| 分類 | 集計対象 |
| --- | --- |
| Vue | 追跡されている`.vue`全体。テンプレート・script・styleを含む |
| アプリのJS/TS | `app/`・`server/`・`i18n/`、旧`modules/`・`plugins/`・`middleware/`・`store/`、`nuxt.config.*` |
| 単独スタイル | `.css`・`.styl`・`.scss`・`.sass`・`.less` |
| その他のJS/TS | 共有定数・生成ツール・リンター設定など、アプリ以外のJS/TS |
| テストのJS/TS | 配置先によらず`*.test.*`・`*.spec.*`。他のJS/TS分類から除く |
| Actions | `.github/workflows/`内のYAML |
| コンテンツJSON | `i18n/locales/`、旧`lang/`・`modules/`内のJSON |
| 設定 | 上記以外のJSON・TOML。ロックファイルを除く |

JS/TSには`.js`・`.mjs`・`.cjs`・`.ts`・`.mts`・`.cts`を含めます。ソースコード合計はVue・アプリのJS/TS・単独スタイル・その他のJS/TS・テストの合計とし、Actions・JSON・TOMLを加えた値は別に示します。物理行数を配信量や保守性そのものとは扱いません。

未コミット変更を示す場合はコミット済みの値と分けます。push後は対象HEADを更新して再集計し、未反映扱いの古い表や説明を残しません。集計方法を変更する場合は比較元も同じ方法で再計算します。

## 作業を引き継ぐとき

進行中の作業状態はPR・Issue・引き継ぎメッセージへ記録します。継続的な方針はAGENTS.md、実装の意図は該当コードのコメントや既存ガイドへ記載し、一時的な進捗メモと分けます。

引き継ぎには、目的と未完了の作業、採用・見送りの決定、ブランチとHEAD、未コミット・未pushの有無、実施した検証と限界、関係するPR・Issue・レビューのリンクを必要な範囲で含めます。改善候補の通し番号を継続する場合は、最後に使った番号と残っている候補も伝えます。

作業終了時に`git status --short`を確認し、commit・pushしたか、変更がローカルに残っているかを明記します。チェックの成功は確認したHEADに結び付け、以前のHEADでの成功を新しい変更の検証結果として流用しません。
